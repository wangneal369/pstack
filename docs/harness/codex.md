# pstack in OpenAI Codex

pstack skills use Cursor names. In Codex (CLI or App), read this file once per session, then map each Cursor name in a skill with the tables below. `<pstack>` means the folder that holds `skills/` and `docs/` (for example `~/.agents/skills/` or your installed pstack root). If a Cursor field has no row, drop it and say so. Never pass a field or value a tool schema rejects.

## Tools

| Cursor | Codex |
| --- | --- |
| `Task` | `spawn_agent` (with `wait` / `send_input` / `close_agent`) when multi-agent is enabled. If multi-agent is disabled in this session, run an isolated `codex exec` child process via shell or execute sequentially and say so. |
| `AskQuestion` | `request_user_input` when available. In non-interactive (`codex exec`) runs it is absent, so ask in plain text or proceed on reversible defaults per `worker.md`. |
| Open a todolist, or copy steps into the todolist tool | `update_plan` (outside read-only Plan Mode). If unavailable, keep the checklist in your reply and update it at each phase. |
| Run another pstack skill (`/name` or "the **name** skill") | Read `<pstack>/skills/<name>/SKILL.md` directly and follow it. When telling the user to invoke a skill explicitly, write `$<name>` (or `/skills`). |
| `Grep`, `Glob` | `rg` / `rg --files` via the shell tool. |
| `watch-pr` (`scripts/watch-pr/watch-pr`) | Run `bun` if installed; if `bun` is unavailable (common on Windows), run `node <pstack>/skills/poteto-mode/scripts/watch-pr/watch-pr.ts` (Node 22.6+ zero-dependency fallback). |

## Subagent fields

| Cursor | Codex |
| --- | --- |
| `subagent_type: generalPurpose` | Default worker agent (`spawn_agent` with default/worker role). |
| `poteto-agent`, `comment-sicko` | Custom agents defined in `~/.codex/agents/poteto-agent.toml` and `~/.codex/agents/comment-sicko.toml` (generated by `generate-harness.mjs`). If absent, spawn a default worker and prepend `Read <pstack>/skills/poteto-mode/worker.md before anything else.` plus the full path to `skills/poteto-mode/SKILL.md` (or `agents/comment-sicko.md`). |
| The `model:` line in `poteto-agent`'s file | It holds a Cursor slug. Never pass a Cursor slug (`claude-*`, `gemini-*`) to Codex APIs. Omit `model` to inherit the session model, or map via the Models table below. |
| `readonly: true` | Spawn an `explorer` / read-only subagent, state `"do not edit any files"` in its brief, and verify `git status` afterward. |
| `readonly: false` | Spawn a default/worker subagent with workspace write access. |
| `environment: "cloud"` | Create a dedicated `git worktree` (e.g. `git worktree add ../wt-<slug> -b <branch> <base>`) and point the subagent at that worktree path. |
| `environment: "local"` | Omit (use current workspace). |
| `cloud_base_branch: <b>` | Base the worktree on `<b>` (or tell the worker to check out `<b>` first). |
| `run_in_background: true` | Omit (`spawn_agent` runs asynchronously; collect with `wait`). |
| `resume` | Use `send_input` on a live agent ID, or spawn a fresh agent and paste the prior report and branch/worktree path into its brief. |
| `file_attachments` | List exact file paths in the brief. |

## Models

| Cursor | Codex |
| --- | --- |
| `claude-*`, `gemini-*`, or any Cursor slug | Omit `model` so the agent runs on the active Codex model, or map to a model configured in `~/.codex/config.toml` (e.g. `gpt-5.4` / your session model) with matching `reasoning_effort` (`low`, `medium`, `high`, `xhigh`). Drop `-fast`. |
| `auto` or `inherit-parent` | Omit `model` (inherit session model). |
| Diverse multi-vendor panels (`arena`, `interrogate`) | If Codex only has single-vendor models, diversify candidates by reasoning effort or explicit design constraints (or shell out to another installed CLI if configured), and note single-vendor mode in the synthesis report. |
| The `pstack-models.mdc` rule (`~/.cursor/rules/pstack-models.mdc`) | `~/.codex/pstack-models.md` (referenced from `~/.codex/AGENTS.md`). Codex never reads `.mdc` files. |

## setup-pstack

Codex reads `~/.codex/AGENTS.md` and project `AGENTS.md`, never `~/.cursor/rules/*.mdc`. Adapt `setup-pstack` as follows:

- **Detect**: Read available models/profiles from `~/.codex/config.toml` and current session capabilities. Never write an unavailable Cursor slug.
- **Defaults**: Map every role to `inherit-parent` (or your configured Codex model + reasoning effort: `xhigh` for `large`, `high` for `medium`, `medium` for `small`).
- **Write**: Write `~/.codex/pstack-models.md` (plain Markdown, no `.mdc` frontmatter) and add a one-line pointer in `~/.codex/AGENTS.md` (`For pstack model overrides, read ~/.codex/pstack-models.md`).

## Cursor-only features

Codex has no Cursor Automations, Bugbot, Cursor cloud agents, or built-in PR tool. When a step needs one, write one line in your reply: `Skipped in Codex: <step>. <reason>.` and continue. Never stop, ask, or retry a missing Cursor feature.

| Cursor | Codex |
| --- | --- |
| Cursor Automations (`routines`, `api2.cursor.sh/automations`, `SendToUser`) | Skip with the one-line note. |
| Bugbot | GitHub PR comments from automated bots are regular review threads; triage them via `gh` and `references/bugbot-triage.md`. Skip steps that start or configure Bugbot itself. |
| Cursor cloud agents | Map `environment: "cloud"` to a local `git worktree`. Skip cloud-dashboard steps. |
| Built-in PR tool | Use `gh` CLI (or `watch-pr.ts` via Node). Not a skip; write no skip line. |
| `cursor-team-kit` (`/deslop`, `control-ui`, `control-cli`) | Run `/no-comments` + `unslop` for deslop; use Playwright/CLI directly (or `/create-verification-skill`) for app control. |
