# pstack in Pi (`pi-coding-agent`)

pstack skills use Cursor names. In Pi (`pi.dev`), read this file once per session, then map each Cursor name in a skill with the tables below. `<pstack>` means the folder that holds `skills/` and `docs/`. If a Cursor field has no row, drop it and say so. Never pass a field or value a tool schema rejects.

## Tools

| Cursor | Pi |
| --- | --- |
| `Read`, `Write`, `Edit`, `Bash` | Pi core tools: `read`, `write`, `edit`, `bash`. |
| `Grep`, `Glob` | `grep` / `find` / `ls` if enabled in Pi, otherwise `rg` / `rg --files` via `bash`. |
| `Task` | If a subagent extension (`pi-subagents` / `pi-sub-agent`) is installed, use its subagent tool. Otherwise spawn an isolated headless Pi subprocess via `bash` (`pi -p --no-session ...`) inside a dedicated `git worktree`, or run sequentially and note it. |
| `AskQuestion` | Ask the user in plain numbered Markdown text and wait for their reply. In non-interactive `pi -p` runs, proceed on reversible defaults per `worker.md`. |
| Open a todolist, or copy steps into the todolist tool | Use your todo extension if installed; otherwise keep a concise Markdown checklist in your reply and update it at each phase. |
| Run another pstack skill (`/name` or "the **name** skill") | Call `read` on `<pstack>/skills/<name>/SKILL.md` and follow it. When telling the user to invoke a skill explicitly, write `/skill:<name>`. |
| `watch-pr` (`scripts/watch-pr/watch-pr`) | Run `bun` if installed; if `bun` is unavailable, run `node <pstack>/skills/poteto-mode/scripts/watch-pr/watch-pr.ts` (Node 22.6+ zero-dependency fallback). |

## Subagent fields

| Cursor | Pi |
| --- | --- |
| `subagent_type: generalPurpose` | Default Pi subagent (or `pi -p` worker with default tools). |
| `poteto-agent`, `comment-sicko` | Subagent definitions at `~/.pi/agent/subagents/poteto-agent.md` and `~/.pi/agent/subagents/comment-sicko.md` (or `.pi/subagents/`), generated by `generate-harness.mjs`. If running without a subagent extension, prepend `Read <pstack>/skills/poteto-mode/worker.md before anything else.` and the absolute path to `skills/poteto-mode/SKILL.md` (or `agents/comment-sicko.md`). |
| The `model:` line in `poteto-agent`'s file | It holds a Cursor slug. Map it to a real `<provider>/<model>` ID available in Pi plus `--thinking <level>` (see Models below), or omit to inherit the session model. |
| `readonly: true` | Restrict subagent tools to `read,grep,find,ls` (or `read,bash` with `"do not edit any files"` in the brief) and verify `git status` afterward. |
| `readonly: false` | Grant full `read,write,edit,bash` tools. |
| `environment: "cloud"` | Create a dedicated `git worktree` via `bash` and set the child's working directory to that worktree. |
| `environment: "local"` | Omit (use current workspace). |
| `cloud_base_branch: <b>` | Base the worktree on `<b>` (or instruct the worker to check out `<b>` first). |
| `run_in_background: true` | Use the subagent extension's background/parallel mode, or launch parallel `pi -p` jobs via `bash` writing to separate output files and wait for all PIDs. |
| `resume` | Spawn a fresh child and pass the prior output, branch, and worktree path in its brief. |
| `file_attachments` | List exact file paths in the brief (or pass `@<path>` if supported by the CLI invocation). |

## Models

Pi is multi-provider natively (`--provider` / `--model` and `--thinking <off|minimal|low|medium|high|xhigh>`), which makes it a strong fit for pstack's multi-model `arena` and `interrogate` panels.

| Cursor | Pi |
| --- | --- |
| `claude-<family>-<version>-<effort>[-fast]` | Your configured Anthropic model ID (e.g. `anthropic/claude-opus-...`) with `--thinking <effort>`. Drop `-fast`. |
| `gemini-<version>-<variant>-<effort>` | Your configured Google/Gemini model ID with `--thinking <effort>`. |
| `grok-*` / OpenAI models | Your configured provider/model ID (e.g. `openai/...`, `xai/...`) with `--thinking <effort>`. |
| `auto` or `inherit-parent` | Omit model override (inherit active Pi session model). |
| The `pstack-models.mdc` rule (`~/.cursor/rules/pstack-models.mdc`) | `~/.pi/agent/pstack-models.md` (referenced from `~/.pi/agent/AGENTS.md`). Pi never reads `.mdc` files. |

## setup-pstack

Pi auto-loads `~/.pi/agent/AGENTS.md` and project `AGENTS.md`, never `~/.cursor/rules/*.mdc`. Adapt `setup-pstack` as follows:

- **Detect**: Run `pi --list-models` via `bash` (or ask the user which configured providers/models they want active). Never write an unverified Cursor slug.
- **Defaults**: Map each role to a real `<provider>/<model> <thinking-level>` pair (where `large` = `xhigh`, `medium` = `high`, `small` = `medium`) or `inherit-parent`. For `arena runners`, `arena cross-judge pool`, and `interrogate reviewers`, pick models from distinct providers when available.
- **Write**: Write `~/.pi/agent/pstack-models.md` (plain Markdown, no `.mdc` frontmatter) and add a one-line pointer in `~/.pi/agent/AGENTS.md` (`For pstack model overrides, read ~/.pi/agent/pstack-models.md`).

## Cursor-only features

Pi has no Cursor Automations, Bugbot, Cursor cloud agents, or built-in PR tool. When a step needs one, write one line in your reply: `Skipped in Pi: <step>. <reason>.` and continue. Never stop, ask, or retry a missing Cursor feature.

| Cursor | Pi |
| --- | --- |
| Cursor Automations (`routines`, `api2.cursor.sh/automations`, `SendToUser`) | Skip with the one-line note. |
| Bugbot | Triage GitHub PR review comments via `gh` and `references/bugbot-triage.md`. Skip steps that start or configure Bugbot itself. |
| Cursor cloud agents | Map `environment: "cloud"` to a local `git worktree`. Skip cloud-dashboard steps. |
| Built-in PR tool | Use `gh` CLI (or `watch-pr.ts` via Node). Not a skip; write no skip line. |
| `cursor-team-kit` (`/deslop`, `control-ui`, `control-cli`) | Run `/skill:no-comments` + `/skill:unslop` for deslop; drive UI/CLI via `bash` / Playwright / `/skill:create-verification-skill`. |
